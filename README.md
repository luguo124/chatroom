# MonadChat 产品介绍

> **基于 Monad 区块链的去中心化端到端加密聊天室**
> 链上身份验证 · 链下加密传输 · 聊天内容永不上链

---

## 一、产品定位

MonadChat 是一款运行于 Monad 区块链之上的私密通讯产品。用户以加密钱包地址作为唯一身份标识，在链上完成房间注册与公钥存证，消息则通过浏览器间的 P2P 加密通道（WebRTC DataChannel）直接传输。

**架构原则：身份与信任上链，内容与隐私离链。**

- 链上仅存储房间元数据（房间名、创建者、成员列表）与成员公钥——可验证、不可篡改
- 聊天消息内容（用户互发的文字）全部以端到端加密密文形式走链下 P2P 通道，任何中间节点（包括运营方）均无法解密
- 全栈零后端依赖、零月度成本，纯 Web 客户端零安装交付

## 二、核心能力

### 1. 链上身份，不可剥夺

- 以 MetaMask 钱包地址作为用户唯一标识，通过 `personal_sign` 签名完成登录认证，无需手机号、邮箱或任何实名信息
- 身份锚定于区块链，不存在可封禁、可注销的中心化账户体系
- 会话凭证本地缓存 24 小时，有效期内免重复签名

### 2. 端到端加密，全程密文

- 加密体系：X25519 ECDH 密钥协商 + HKDF-SHA256 密钥派生 + AES-GCM-256 认证加密，全部由浏览器原生 Web Crypto API 实现
- 消息在发送端加密、接收端解密，信令服务器、TURN 中继、离线存储数据库接触到的均为密文
- 用户公钥写入 PrivateChatRoom 合约并发出链上事件，任何人可通过第三方 RPC 独立核验，杜绝中间人攻击

### 3. P2P 直连，低延迟传输

- 在线消息走 WebRTC DataChannel 点对点直连，不经过任何消息服务器中转
- 复杂 NAT 环境自动回退 Metered TURN 中继（免费 1TB/月），中继仅转发密文
- 信令交换基于 Supabase Realtime Broadcast，建连即焚、不落盘

### 4. 离线暂存，限时销毁

- 接收方离线时，密文经钱包签名验证后暂存于 Supabase PostgreSQL（Edge Function 验签，RLS 默认拒绝直接访问）
- 接收方上线自动拉取、本地解密，全程非阻塞 UI
- 暂存密文 24 小时后由 pg_cron 自动物理删除，不留副本

### 5. 本地持久化，数据自主

- 聊天记录仅存于本机 IndexedDB，服务端零留存
- 支持分页加载历史消息
- 用户对数据拥有完全控制权：清除即彻底消失，包括运营方在内的任何一方均无法恢复

## 三、技术架构

```
┌────────────────────────────────────────────────────────────┐
│  Web 客户端（React 19 + TypeScript，零安装）                │
│  ├─ WalletService      MetaMask / personal_sign 验签        │
│  ├─ E2EEService        X25519 + HKDF + AES-GCM-256          │
│  ├─ WebRTCChatService  RTCPeerConnection DataChannel        │
│  ├─ WebStorageService  IndexedDB（Dexie.js）                │
│  └─ RoomContract       viem 合约交互                         │
└──────────┬───────────────┬──────────────────┬──────────────┘
           │               │                  │
           ▼               ▼                  ▼
   Monad Testnet     Supabase            Metered TURN
   ├─ 身份/公钥存证   ├─ Realtime Broadcast  └─ NAT 穿透回退
   ├─ 房间注册       │   （信令，不落盘）       （仅转发密文）
   └─ 成员管理       └─ PostgreSQL
                      （离线密文，24h 销毁）
```

- **部署**：Cloudflare Pages 全球 CDN，自动 HTTPS
- **成本**：全栈 $0/月（CF Pages + Supabase 免费层 + Metered 免费额度 + Monad Testnet）
- **性能**：Monad 出块 300ms / 终局 600ms；P2P 消息延迟 < 500ms

## 六、扩展路线

当前 MVP 已完成钱包身份、链上房间、E2EE 消息、P2P 传输、离线暂存与 Web 客户端的完整闭环。身份层、加密层、传输层三块基础能力均已就绪，可沿以下方向自然演进：

### 体验增强

- **WalletConnect v2**：移动端钱包扫码接入，摆脱浏览器插件依赖
- **ERC-4337 账户抽象**：Smart Account + Paymaster 实现 gasless 交互，降低新用户门槛（Monad 已部署 EntryPoint v0.6/0.7/0.8）
- **Tauri 桌面客户端**：常驻后台、系统通知、全局快捷键
- **WebAuthn / Passkey**：基于 Monad 原生 P256 预编译（0x0100）实现生物识别认证

### 功能演进

- 富媒体消息（图片 / 文件 / 语音）：复用现有加密管道，扩展消息类型
- 大规模群聊：mesh 拓扑升级为混合中继，配合 Monad 万级 TPS 支撑链上成员管理
- 消息自毁与阅后即焚：离线密文定时销毁机制的策略化延伸
- 加密备份与恢复：助记词派生密钥，跨设备迁移

### 生态场景

- **DAO 私密议事厅**：持币门槛验证入房，治理讨论全程加密
- **NFT/OTC 场外交易协商**：钱包对钱包的保密议价通道
- **链上客户服务**：项目方开设验证房间，持币用户凭地址接入
- **Monad 主网迁移**：testnet 验证后切换主网，触达 400 万+ 钱包用户
- **Web3 私信 SDK**：向第三方 DApp 开放钱包间加密通讯能力

## 七、常见问题

**Q：运营方能否读取用户消息？**
不能。消息在发送端加密、接收端解密，密钥仅存在于双方设备，任何中间环节均不持有解密能力。这由加密算法保证，而非运营承诺。

**Q：清除浏览器数据后聊天记录是否可恢复？**
不可恢复。记录仅存于本机 IndexedDB，服务端无任何备份。如需留存请自行导出。

**Q：应用能否获取钱包私钥？**
不能。私钥始终处于 MetaMask 沙箱内，应用仅能通过 EIP-1193 标准接口发起受限的签名请求。
